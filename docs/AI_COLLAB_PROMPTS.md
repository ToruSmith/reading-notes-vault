# 讓 Claude 讀你的公開筆記、幫你畫畫布與寫筆記

## 一、可行性（先看這個）

| 想做的事 | 可行嗎 | 方式 |
| --- | --- | --- |
| Claude 讀你的**公開**筆記、畫布、SVG | 可行 | 讀取網址的 REST 讀取（下方第二節），或靜態網站頁面 |
| Claude 讀你的**私人**筆記 | 不開放（刻意設計） | 讀取網址一律只回公開內容；要讓 Claude 看私人內容，只能由你自己匯出後貼給它或上傳 |
| Claude **直接寫入**你的 Vault | 不建議、預設做不到 | 寫入需要你的 Google 登入，且前端沒有任何金鑰，這是安全設計，不要為了方便開洞 |
| Claude **產出檔案**，你一鍵匯入 | 可行，推薦 | Claude 產出 `.canvas`、`.md`、`.svg`，你用「匯入」或「上傳」放進去（第三節） |
| 讓 Claude 操作你已登入的瀏覽器代為點擊 | 技術上可行，需你盯著 | 使用 Claude in Chrome 並限制它只能開你的編輯網址；每個寫入動作你都要看過再放行。不是必要，也不是最穩的路 |

兩個重要提醒：
1. **Claude 能不能連到網址，取決於你用的 Claude 環境有沒有網路／網頁讀取功能**，以及該環境是否允許連到 `script.google.com` 和 `script.googleusercontent.com`（Apps Script 的網址會轉址到後者）。我在製作這份文件時**沒有用你的實際網址驗證過**，請你用第二節的「連線測試」先試一次。連不上時請改用第四節的備案。
2. **讀取網址上的畫布是訪客版**：私人筆記的卡片已被拿掉。所以不要把 Claude 改過的訪客版畫布直接「匯入」去取代你的真實畫布，否則私人卡片會不見。第三節有安全做法（匯入在你按「儲存」前不寫入，而且可復原，仍請照著做）。

## 二、讓 Claude 讀公開筆記

### 2.1 你的網址（填進下面的提示詞）
- 讀取網址：`https://script.google.com/macros/s/＿＿＿＿＿/exec`
- 靜態站（若有設）：`https://＿＿＿.pages.dev`

### 2.2 REST 介面（只讀，一律訪客視角）

在讀取網址後加參數，回傳 JSON：

| 目的 | 網址 | 回傳重點 |
| --- | --- | --- |
| 列出所有公開筆記與主題 | `<讀取網址>?action=listIndex` | `items[]`：`id`、`title`、`topic`、`date`、`tags`、`lang`、`cover`…；`topics[]`：`id`、`title`、`category` |
| 讀一則筆記 | `<讀取網址>?action=getNote&id=<id>` | `meta`、`body`（Markdown，指向私人的連結已改成「（未公開的筆記）」） |
| 讀某主題的畫布 | `<讀取網址>?action=getBoard&topic=<topic-id>` | `board.nodes`、`board.edges`（私人卡片已拿掉） |
| 讀一個 SVG | `<讀取網址>?action=getSvg&id=<id>` | SVG 原始碼 |

id 格式是 `YYYYMMDD-xxx`，例如 `20261022-a1`；主題 id 是小寫英數與連字號，例如 `db-design`。找不到或私人的項目一律回「找不到」，兩者無法區分。

### 2.3 提示詞：連線測試（先做這個）

```text
請用你的網頁讀取功能，打開下面這個網址，告訴我你看到什麼（筆記數量、前 5 則的標題與 id、主題清單）。
如果打不開，請照實告訴我是哪個步驟失敗（網路被擋、轉址失敗、回傳不是 JSON…），不要猜測內容。

<讀取網址>?action=listIndex
```

### 2.4 提示詞：讀取與整理

```text
你是我的「讀書筆記 Vault」助理。我的 Vault 有一個唯讀的公開網址：
  讀取網址：<填你的讀取網址>

規則：
1. 只能用這四種讀取（都是 GET）：
   ?action=listIndex／?action=getNote&id=<id>／?action=getBoard&topic=<topic-id>／?action=getSvg&id=<id>
2. 你看到的只有「公開」內容。若某筆記回「找不到」，代表它不存在或是私人，不要猜，也不要要求我貼私人內容，除非我主動給。
3. 回答時引用筆記要附標題與 id。沒有讀到的內容不要編造。
4. 若讀取失敗（打不開、不是 JSON），直接告訴我，並請我貼上內容。

先做：呼叫 listIndex，用表格列出每個主題與其筆記數，然後問我想處理哪個主題。
```

## 三、讓 Claude 產出畫布與筆記（推薦）

### 3.1 流程
1. Claude 讀公開筆記（第二節），或你直接貼筆記給它。
2. Claude 輸出檔案內容：`.canvas`（畫布）、`.md`（筆記）、`.svg`（圖）。
3. 你把它存成檔案，再放進 Vault：
   - 畫布：編輯網址開某主題的畫布 →「匯入」→ 選檔 → 確認無誤再按「儲存」。匯入會取代畫面上的畫布，但未儲存前不寫入雲端，也可以按復原。
   - 筆記與 SVG：右上「上傳」。整個資料夾上傳時，資料夾名會成為主題。

### 3.2 最安全的做法
- **不要讓 Claude 改你的現有畫布**，而是請它產出一張**全新**的畫布，匯入到一個**新的空主題**（或先在畫布頁「匯出」備份目前版本）。滿意後再手動搬卡片。
- 要引用已存在的筆記，只能用 `listIndex` 看得到的 id；新寫的內容請用「便利貼（text）」卡片，因為新上傳筆記的 id 是上傳時才產生的，Claude 事先不知道。

### 3.3 格式規格（提供給 Claude）

**畫布 `.canvas`（JSON Canvas 格式）**
```json
{
  "nodes": [
    { "id": "g1", "type": "group", "label": "第三章", "x": -40, "y": -60, "width": 740, "height": 280, "color": "4" },
    { "id": "n1", "type": "file", "file": "notes/20261022-a1.md", "x": 20, "y": 30, "width": 260, "height": 140, "x-parent": "g1" },
    { "id": "t1", "type": "text", "text": "重點：…（支援 Markdown）", "x": 320, "y": 30, "width": 260, "height": 140, "x-parent": "g1" },
    { "id": "l1", "type": "link", "url": "https://www.youtube.com/watch?v=…", "x": 640, "y": 0, "width": 480, "height": 270 }
  ],
  "edges": [
    { "id": "e1", "fromNode": "n1", "toNode": "t1", "fromEnd": "none", "toEnd": "arrow", "label": "延伸", "color": "1", "x-style": "dashed" }
  ]
}
```
- `type`：`group`、`file`、`text`、`link`。座標與大小用整數；`id` 在整張畫布內不可重複。
- `file` 只能指向實際存在的 `notes/<id>.md`。
- 群組成員用 `x-parent` 指向群組 id；子卡片必須在群組範圍內。群組可巢狀。
- `color` 是字串 `"1"`～`"6"`；`x-style` 只能是 `solid`／`dashed`。
- 自訂欄位一律 `x-` 開頭；不認得的欄位會原樣保留。
- 卡片排版建議：卡片寬 240–320、高 120–200，間距 40 以上，群組外框四周留 40。
- 連結只能 `http`／`https`。
- 連結卡片可附 `x-preview`（物件，選填）：`title`（≤120 字）、`description`（≤240 字）、`image`（https 網址，可省略）、`site`（≤60 字）。內容必須是你實際讀到的，不要編造。
- SVG 圖片卡：`{ "type": "file", "file": "assets/<id>.svg", … }`，id 必須是你實際讀到的（筆記引用或封面的 SVG）。

**筆記 `.md`**
```markdown
---
title: 筆記標題
date: 2026-10-24
tags: [標籤一, 標籤二]
lang: zh-Hant
public: false
---
內文（Markdown）。連到另一則筆記用 [[另一則筆記的標題]]。
嵌入 SVG：![說明](圖檔名.svg)
```
- 上傳時系統會自己指定 id，所以**不要**自己寫 `id`。
- `public` 預設請寫 `false`，由我自己看過再決定公開。
- 放進資料夾上傳，資料夾名稱就是主題名稱。

**SVG**
- 要有 `viewBox`；不可含 `<script>`、事件屬性（`onclick` 等）、`<foreignObject>`、外部連結、外部 `url()`、內嵌點陣圖（base64 png／jpeg）。違規的內容會被拒絕或被清除。

### 3.4 提示詞：產出畫布

```text
你是我的「讀書筆記 Vault」排版助理。我會給你一組筆記（或讓你從 <讀取網址> 讀取公開筆記），
請幫我產出一張**全新**的畫布檔（.canvas，JSON Canvas 格式），主題：<主題名稱>。

做法：
1. 先列出你打算怎麼分群（群組名稱、各群組有哪些筆記），給我確認。我說「可以」之後再輸出檔案。
2. 輸出時只給一個 json 程式碼區塊，不要混入說明文字。
3. 規格：
   - nodes 的 type 只用 group／file／text／link；file 的路徑一律是 notes/<id>.md，且 id 必須是你實際讀到的（listIndex 內有的）；不確定的 id 不要用。
   - 沒有現成筆記的內容，用 text 便利貼卡片。
   - 群組用 x-parent 放入子卡片，子卡片完整落在群組範圍內；群組四周留 40 的邊界。
   - 卡片寬 240–320、高 120–200，水平與垂直間距至少 40，不可重疊。
   - 連線 edges：fromNode／toNode 必須是已存在的卡片 id；label 寫關係（例如「延伸」「反例」「前提」）；color 用 "1"～"6"；虛線用 "x-style": "dashed"。
   - id 全部不重複；座標與尺寸一律整數。
4. 輸出後自我檢查：id 是否重複、edge 端點是否存在、子卡片是否在群組內、有沒有卡片重疊，並簡短列出檢查結果。
5. 絕對不要在畫布裡放你沒讀到的筆記內容。
```

### 3.5 提示詞：產出筆記與 SVG

```text
請把下面的素材整理成讀書筆記，輸出為可直接上傳到我的 Vault 的檔案。

素材／主題：<貼上素材或說明>

規格：
- 每則筆記一個 .md 檔，檔頭是 YAML front matter：title、date（今天）、tags、lang（zh-Hant 或 en）、public: false。不要寫 id。
- 內文用 Markdown；提到我已有的筆記時用 [[標題]]；需要圖時另產出 .svg，用 ![說明](檔名.svg) 引用。
- SVG 必須有 viewBox，不可含 script、事件屬性、foreignObject、外部連結、外部 url()、內嵌點陣圖；文字用系統字型。
- 請告訴我建議的資料夾名稱（會成為主題）與每個檔名。
- 每個檔案用獨立的程式碼區塊輸出，區塊前一行寫檔名。
```

## 四、連不上時的備案

1. **貼給它**：把公開筆記複製貼進對話。
2. **上傳**：在編輯網址「備份」頁匯出 ZIP，解壓後把需要的 `notes/*.md`、`boards/*.canvas.json` 上傳給 Claude。**注意：ZIP 內含你全部的私人筆記，只上傳你願意讓它看的檔案。**
3. **靜態站**：若有設定靜態網站，Claude 可以讀 `https://＿＿＿.pages.dev/zh/` 的頁面（它是公開內容的快照，更新要先按「立即同步」）。

---

## 五、安全提醒
- 不要把編輯網址、`GITHUB_TOKEN` 或任何權杖貼給 Claude；它不需要。
- 讓 Claude 看私人內容之前，確認你的 Claude 方案與資料使用設定符合你的期待。
- Claude 產出的筆記預設 `public: false`；公開前用編輯網址的「發布檢查」看過一次（含個資掃描）。
