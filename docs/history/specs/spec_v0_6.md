# 讀書筆記 Vault 技術規劃書 v0.6

Oct 22, 2026 · @Toru Smith

## 1. 目標與範圍

本專案要做一套**個人讀書與寫作空間**：資料全是 Markdown（MD）與 SVG 純文字檔，用網頁瀏覽與編輯，能在 Obsidian Canvas／Heptabase 風格的畫布上整理知識，並把選定的筆記公開成網站。使用者是單一個人，目標規模 200 本書以上，畫布編輯在電腦，手機與平板可上傳與編輯文字筆記、畫布唯讀。

**核心原則**

1. 資料與介面分離：筆記永遠是可帶走的檔案（`.md`、`.svg`、`.canvas`），不被平台綁住。
2. 全程免費、不綁信用卡。
3. 只用 MD 與 SVG，不處理點陣圖（PNG、JPG）上傳；圖片僅允許外部連結。
4. 本機優先、可漸進：每個階段都能獨立使用。
5. 格式相容 Obsidian 的 JSON Canvas，日後可改用 Obsidian 開啟。

**範圍內**

- 三種檢視：網狀畫布（含群組）、圖庫、日曆
- 在公開網頁上，經驗證後直接上傳與編輯 MD、SVG（手機、平板限文字筆記）
- 筆記間 `[[連結]]`、反向連結、搜尋（含中文）
- 中英雙語介面與內容、可換配色主題
- 公開發布與手機、平板唯讀閱讀

**範圍外**

- Notion 連動、多人協作、即時共編
- 手機端畫布觸控編輯、PDF 內標註
- 點陣圖與 PDF 的檔案上傳（資料格式預留，之後可開）

- D30：儲存衝突（409）不自動覆蓋。選項：合併（依 id 三方合併；兩邊都改同一項以我的為準；一邊刪、一邊改則保留被改的）、用我的覆蓋（二次確認）、另存我的版本（下載）、放棄我的修改。

- D32：畫布可匯出、匯入 `.canvas`（Obsidian 相容）；匯入視為取代目前畫布並可復原，按「儲存」才寫入。
- D33：手機、平板的畫布維持唯讀（`canvasTouchEdit: false`），可平移與縮放；擁有者仍可在手機編輯文字筆記。
- D34（雙語）：介面字串以「中文原文當鍵」，程式一律寫 `T('原文', 參數…)`，佔位符 `{1}`、`{2}`；語言檔 `frontend/i18n/<語言>.json`，新增語言只需加一個 JSON（含 `"@name"`）。後端回的訊息保持中文，前端用範本鍵反向比對翻譯。預設跟隨瀏覽器語言（zh→繁中，其餘英文），可在設定手動切換並記住（IndexedDB）。筆記的 `lang` 欄位只用於篩選。測試強制：程式裡不得有未包 `T()` 的中文、兩個語言檔鍵集一致、英文不含中文字、佔位符相同。

- D36（檢視）：列表／圖庫／日曆讀同一份索引；切換不寫入任何資料（測試以呼叫計數驗證）。圖庫縮圖用 `cover` 的 SVG，進入可視範圍才取，一律 `<img>`。日期範圍與排序同時作用於列表與圖庫。日曆以 `date` 分格（手動解析 YYYY-MM-DD，不受時區影響），雙擊（擁有者）或「在這天新增筆記」開編輯器，帶入該日與目前所選主題，沒選主題則未歸類。
- D37（全文索引快取）：擁有者的筆記內文索引快取在瀏覽器 IndexedDB（`vault-ft`），再開時只補抓 `updatedAt` 不同的筆記（超過 60 則改整批重建）；以訪客身分載入會清掉快取。
- D20：單檔大小只做提醒，不擋存檔（取代 6.2「超過即拒絕」中的大小限制；不含對非擁有者的拒絕）。建議值為 MD 與 SVG 各 100 KB，超過時回傳警告。另設 5 MB 的技術防線，只為避免單次請求拖垮 Apps Script，數值可調。

## 4. 資料模型

**核心概念**：筆記是內容，畫布是排版。同一則筆記可出現在多張畫布，位置與關係屬於「這張畫布」，不寫進筆記本身。

### 4.1 Drive 資料夾

```text
Vault/
├─ notes/<id>.md                 筆記本文（含 YAML front matter）
├─ assets/<id>.svg               SVG 檔
├─ topics/<topic-id>.json        主題設定（名稱、分類、預設公開）
├─ boards/<topic-id>.canvas.json 畫布：座標、群組、連線
├─ themes/<name>.json            自訂配色
└─ _backup/                      每月 ZIP
```

- 檔名一律用 `id`（日期加短碼，例如 `20261022-a1`），不用原檔名，避免中文、空白、重名。原檔名記在 front matter 的 `source:`。
- Drive 以隨機檔案 ID 定位檔案，同資料夾可有同名檔，因此必須靠 Sheets 索引記錄「筆記 id → Drive 檔案 ID」。
- 更新一律**覆寫同一個檔案**（檔案 ID 不變），連結才穩定。

### 4.2 筆記 front matter

```yaml
---
id: 20261022-a1
title: MySQL utf8mb4
topic: db-design       # 主題 id；顯示名稱讀自 topics/<id>.json
date: 2026-10-22       # 日曆檢視用
tags: [mysql, 編碼]    # 圖庫篩選用
cover: 20261022-b2     # 圖庫縮圖：SVG 的 id（可省略）
lang: zh-Hant          # zh-Hant 或 en
public: true           # 未填時沿用主題預設
source: 原檔名.md
---
```

一份 front matter 同時支援四個功能：`date` 給日曆、`tags` 與 `cover` 給圖庫、`public` 給發布、`lang` 給雙語。解析需使用正式 YAML 函式庫，不可自行用字串切割。

### 4.3 Sheets 索引（工作表 `index`，一筆記一列）

| 欄位 | 說明 |
| --- | --- |
| id | 筆記 id，主鍵 |
| title、topic、date、tags、lang、public | 由 front matter 複製，供列表與篩選，不必開檔。`topic` 為主題 id |
| cover | 圖庫縮圖指向的 SVG id |
| driveFileId | 對應的 Drive 檔案 ID |
| updatedAt | 最後更新的 ISO 時間，用於衝突偵測 |
| links | 該筆記內 `[[連結]]` 指向的 id，以逗號分隔，供反向連結。筆記內一律存 id；編輯器可用標題搜尋後自動轉成 id |
| svgs | 內文以 `![說明](assets/<id>.svg)` 引用的 SVG id，以逗號分隔，供「被公開筆記引用即公開」的判斷，可由掃描重建 |

Sheets 只是目錄。損毀時由「掃描 Drive 全部 `.md` 並解析 front matter」重建，所以不需要特別保護。

### 4.4 畫布檔格式（JSON Canvas ＋ `x-` 自訂欄位）

```json
{
  "nodes": [
    { "id": "g1", "type": "group", "label": "第三章",
      "x": -40, "y": -60, "width": 740, "height": 280, "color": "4",
      "x-collapsed": false },
    { "id": "g2", "type": "group", "label": "3.1 小節",
      "x": 0, "y": 0, "width": 340, "height": 200, "x-parent": "g1" },
    { "id": "n1", "type": "file", "file": "notes/20261022-a1.md",
      "x": 20, "y": 30, "width": 260, "height": 140, "x-parent": "g2" },
    { "id": "n2", "type": "link", "url": "https://www.youtube.com/watch?v=...",
      "x": 400, "y": 0, "width": 480, "height": 270 }
  ],
  "edges": [
    { "id": "e1", "fromNode": "n1", "toNode": "n2",
      "fromEnd": "none", "toEnd": "arrow",
      "label": "反例", "color": "1", "x-style": "dashed" }
  ]
}
```

| 要記錄的 | 欄位 |
| --- | --- |
| 卡片位置與大小 | `x`、`y`、`width`、`height`（絕對座標） |
| 卡片指向的內容 | `file`（相對路徑）、`url`（外部連結）、`text`（畫布內的便利貼） |
| 關係名稱、顏色 | `edges[].label`、`color` |
| 方向 | `fromEnd`、`toEnd` 設為 `arrow` 或 `none` |
| 實線或虛線 | `x-style`（標準格式沒有，Obsidian 會忽略） |
| 群組成員 | 子節點的 `x-parent` 指向群組 id，形成一棵樹 |
| 群組收合 | 群組的 `x-collapsed` |

**實作規則**

- 所有自訂欄位以 `x-` 開頭，讀取時遇到不認得的欄位必須原樣保留、寫回，不可刪除。
- 放開滑鼠時才判斷歸屬：卡片中心點落在哪個最小的群組內，就更新 `x-parent`。
- 搬動群組時，同步更新所有子孫節點座標。
- 收合時隱藏子孫，連到子孫的線改接到該群組。
- 筆記內的 `[[連結]]` 產生「隱性連線」，不寫進畫布檔，用於反向連結與找出「未放上任何畫布的筆記」。
- 日曆與圖庫不需額外儲存，分別讀 `date` 與 `cover`、`tags`。

### 4.5 公開規則與 `topic.json`

`topics/<topic-id>.json` 記錄主題層級設定：

```json
{
  "id": "db-design",
  "title": "資料庫設計",
  "category": "資料庫",
  "status": "reading",
  "defaultPublic": false
}
```

- 判斷順序：筆記有 `public` 就用筆記的；沒填就用所屬主題的 `defaultPublic`；主題也沒設則視為私人。
- 畫布沒有自己的開關，隨主題：主題公開才可被未登入者讀取，且只回傳公開的卡片。
- SVG 沒有自己的開關：被任何公開筆記或公開畫布引用，即視為公開。
- 預設值：`journal` 主題為公開，讀書類主題為私人。

## 5. 前端規格

前端是單頁網頁應用，載入後只讀 Sheets 索引，打開某個主題才載入該主題的筆記與畫布（延遲載入）。三種檢視共用同一批筆記，切換檢視不改資料。

### 5.1 三種檢視

| 檢視 | 適合情境 | 讀取的欄位 | 必備功能 |
| --- | --- | --- | --- |

### 5.4 技術選擇

- 第一版以**單一 HTML 檔＋原生 JS**起步，自製 SVG／DOM 畫布，免建置流程，可直接部署到 GAS。
- 若畫布功能膨脹，再評估改用 Vite 加輕量框架，或現成節點編輯庫（如 React Flow，內建父子節點、縮放、小地圖）；該決定留到 P2 結束後再做。
- Markdown 用 markdown-it 或 marked；YAML 用正式函式庫；搜尋用 MiniSearch 或 FlexSearch，中文以 `Intl.Segmenter` 分詞。

### 5.5 SVG 的安全規則

- 一律用 `<img src>` 顯示 SVG，**不內嵌進頁面 DOM**，避免 SVG 內的腳本被執行。
- 上傳時拒絕含 `<script>`、事件屬性（`onload` 等）、`<foreignObject>` 的 SVG，或在上傳端清除。
- 不接受內嵌 base64 點陣圖的 SVG（檔案會暴增）。
- SVG 內的中文字型在他人裝置可能不同，重要圖表建議將文字轉成路徑。

## 6. 後端 API 與安全

後端是一支 Google Apps Script（`Code.gs`），部署為網頁應用程式。它是**唯一**能寫入 Drive 與 Sheets 的入口；前端不持有任何金鑰。

### 6.1 端點

| 動作 | 方法 | 驗證 | 說明 |
| --- | --- | --- | --- |
| `listIndex` | GET | 公開（只回 `public` 為真的列）；已驗證則回全部 | 回傳索引與主題清單（訪客只含公開主題） |
| `getNote` | GET | 同上，私人筆記需驗證 | 回傳 MD 本文 |
| `getBoard` | GET | 同上 | 回傳畫布 JSON |
| `saveNote` | POST | 必須 | 建立或更新筆記，同步更新索引 |
| `saveBoard` | POST | 必須 | 覆寫畫布檔，附 `baseUpdatedAt` |
| `uploadSvg` | POST | 必須 | 驗證並清除 SVG 後存入 `assets/`；內嵌點陣圖的 SVG 一律拒絕 |
| `getSvg` | GET | 公開（只回被公開筆記或公開畫布引用的 SVG）；已驗證則回全部 | 回傳 SVG 文字，前端放進 `<img>` |
| `exportBatch` | POST | 必須（僅擁有者） | 分批回傳筆記全文（以最後 id 為游標，每批最多 100 則），供 ZIP 備份與全文搜尋 |
| `exportAssets` | POST | 必須（僅擁有者） | 分批回傳全部 SVG，含沒被引用的孤兒檔 |
| `saveTopic` | POST | 必須 | 建立或更新主題（`topics/<id>.json` 與索引）；私人改公開時須附 `confirmPublic` |
| `deleteNote` | POST | 必須 | 移到 Drive 垃圾桶，不做永久刪除 |
| `rebuildIndex` | POST | 必須 | 掃描 Drive 重建索引 |

讀取與寫入分成不同入口，公開讀取不需任何憑證。

### 6.2 驗證（最重要的安全項）

公開網頁上的上傳功能若沒鎖，任何人都能寫入 Drive。必須擇一實作：

1. **Google 登入**：網頁取得登入者身分，GAS 比對 Email 是否等於擁有者帳號，不符即拒絕。為首選。
2. **共用密碼**：密碼存在 GAS 的指令碼屬性，不寫進網頁原始碼；比對失敗需延遲回應並計次限制。

**已選方案（D15）**：以首選方案「Google 登入」為基礎，採兩個部署實作，細節與驗收見 D15。

共同規則：

- 所有寫入端點先驗證、再處理；驗證失敗回傳通用錯誤，不透露原因。
- 私人筆記不放在公開可讀的路徑，由 GAS 依 `public` 欄位決定是否回傳內容。
- 上傳內容大小設上限（MD 與 SVG 皆為小檔），超過即拒絕。
- 檔名不接受使用者輸入，由伺服器產生 `id`。

### 6.3 衝突處理

電腦與平板可能同時開著。每次寫入附上 `baseUpdatedAt`；若與伺服器的 `updatedAt` 不符，回傳 `409` 與伺服器版本，前端提示「合併、覆蓋或另存」，**不可靜默覆蓋**。

### 6.4 前端呼叫的已知雷點

- 若前端與 GAS 不同網域（升級到 Cloudflare Pages 後），POST 需使用「簡單請求」（`Content-Type: text/plain`，內容自行放 JSON 字串）以避開瀏覽器預檢，否則會被擋。
- GAS 網頁預設包在 iframe 內，部分瀏覽器對 iframe 內的儲存與登入有限制，需實測。
- 冷啟動延遲：前端要有載入中狀態，並快取索引。

### 6.5 配額與備份

- GAS 與 Drive 都有每日配額與單次請求大小上限，**數值請工程師動工前對照官方文件核對**，本文不引用。批次匯入 200 本書須分批、可續傳。

### 6.6 公開內容過濾（P1 必做）

未登入者的所有讀取，都由後端依 4.5 過濾後才回傳；前端不負責隱藏。

- `listIndex`：只回公開筆記的列。
- `getNote`：私人筆記回通用的「找不到」，不透露是否存在。
- `getBoard`：主題公開才回傳；回傳前移除指向私人筆記的卡片、連到這些卡片的連線，以及因此變空的群組。
- 公開筆記內的 `[[連結]]` 若指向私人筆記，回傳時轉成純文字。
- 圖庫、日曆、搜尋索引、反向連結數都用過濾後的結果計算，避免從數量或標題推測出私人內容。
- 驗收：以未登入身分遍歷所有端點，不得出現任何私人筆記的標題、內文或檔名。

### 6.7 手機、平板上傳（分兩段）

- **第一段**：登入、選檔上傳、修改 front matter、文字框編輯 MD。沿用同一組 API，不新增端點，P1 起即開放。
- 登入在 iOS Safari 與 Android Chrome 的 iframe 內可能受限，P1 就要用真機實測；不行則改成獨立分頁開啟網頁應用程式。
- **第二段（另案評估）**：畫布觸控編輯。拖曳、框選、群組、連線會與捲動和雙指縮放衝突，需重新設計操作，等電腦版穩定後再議。
- 行動網路易中斷：草稿存 IndexedDB，失敗可重送，且寫入以 `id` 去重，重送不會產生重複筆記。

**為日後開放而預留（設計規則）**：手機、平板的編輯能力用功能旗標控制，例如 `FEATURES = { mobileEdit: true, canvasTouchEdit: false }`。版面第一版就做成響應式，編輯相關的 API 與電腦共用同一組；日後要開放畫布觸控編輯，只需實作操作方式並把旗標打開，不必改資料格式或後端。

## 7. 發布、雙語、搜尋與配色

### 7.1 發布與手機唯讀

- 公開網頁就是手機、平板的閱讀入口；畫布一律唯讀（可平移、縮放）；登入後的擁有者可在手機、平板上傳與編輯文字筆記，見 6.7。
- 筆記以 `public: true`（或主題預設公開）決定是否出現在公開索引。
- **階段一**：由 GAS 網頁直接供應，免額外服務。
- **階段二（選配）**：靜態網站放 Cloudflare Pages，筆記改由建置程式輸出 HTML，上傳仍經 GAS。需注意：
  - 免費版 GitHub Pages 無法使用私人 repo，Cloudflare Pages 才能連私人來源（請動工前核對官方方案）。
  - Cloudflare Pages 的檔案數與單檔大小有上限，純文字網站遠低於上限，但需核對。
- 版型參考 bobochen.dev：窄欄閱讀寬度、清楚標題階層、目錄、上一篇與下一篇。

### 7.2 日記公開的保險

- `journal` 主題預設公開，單篇可標 `public: false`。
- 發布前自動掃描電話、Email、地址、身分證格式，列出清單供確認；只提醒，不阻擋。
- 發布前提供預覽，看得到這次會公開哪些篇。
- 若日後使用 Git 存放原始碼，來源 repo 必須維持私人，否則 Git 歷史會讓已刪內容仍可被找到。

### 7.3 著作權提醒

讀書類主題預設不公開。公開時以自己的整理、心得、提問為主，避免大段摘抄原書。這是一般性提醒，不是法律意見。

### 7.4 雙語（繁體中文與英文）

| 層面 | 做法 |
| --- | --- |
| 介面文字 | 獨立語言檔 `zh-Hant.json`、`en.json`，加語言不改程式 |
| 筆記語言 | front matter 的 `lang`；一篇一種語言，可用 `translation_of` 連到另一語言版本 |
| 公開網站 | 路徑分 `/zh/` 與 `/en/`，頁首可切換，互為翻譯的文章彼此連結 |
| 搜尋 | 中文無空格，用 `Intl.Segmenter` 或雙字元切分建索引 |
| 字型 | 中文 Noto Sans TC，程式碼用等寬字型；行距中文約 1.75、英文約 1.6，可調整 |
| 日期 | 儲存一律 `YYYY-MM-DD`，顯示依語言 |

### 7.5 配色主題

- 所有顏色以 CSS 變數定義，一個主題就是一份 JSON，存在 `themes/`。
- 每個主題含：背景 2 層、前景文字、弱化文字、主色、輔色、邊框、強調色，以及程式碼高亮 8 色。
- 預設主題：Paper、Paper Dark、Sepia、Tokyo Night、Dracula、Nord；待加 Catppuccin Mocha、One Dark、Gruvbox Dark、Solarized Light。
- 使用者之後會提供配色參考圖，屆時依圖取色，產出 3 到 4 個變形，並檢查文字與背景的對比度。
- 畫布顏色採 Obsidian 的 6 個預設色編號，主題決定各編號的實際色。

## 9. 風險與對策

| 風險 | 影響 | 對策 |
| --- | --- | --- |
| 公開上傳端點被濫用 | 陌生人寫入或塞爆 Drive | 6.2 的驗證、大小上限、失敗計次；伺服器產生檔名 |
| 惡意 SVG 內含腳本 | 瀏覽者被攻擊 | 上傳時清除腳本與事件屬性；顯示一律用 `<img>` |
| 兩台裝置同時編輯 | 後存者蓋掉先存者 | `baseUpdatedAt` 比對，衝突時提示而非覆蓋 |
| Google 帳號被停權或兩年閒置被清 | 全部資料遺失 | 每月 ZIP 備份並存第二處；雙重驗證；帳號保持活躍 |
| GAS 與 Drive 配額、冷啟動 | 匯入中斷、操作變慢 | 分批可續傳、載入狀態、索引快取；動工前核對官方配額 |
| 索引與檔案不同步 | 列表與內容不一致 | `rebuildIndex` 由 Drive 掃描重建 |
| 公開日記含個資 | 隱私外洩 | 單篇可標私人、發布前掃描與預覽 |
| 讀書筆記引用過多原文 | 著作權爭議 | 讀書主題預設不公開，以自己的整理為主 |
| 自製畫布維護成本高 | 進度拖延 | 相容 JSON Canvas；必要時改用現成節點編輯庫 |
| 免費額度或政策改變 | 服務中斷 | 資料全為標準檔案，可隨時搬家；定期重新核對額度 |
| 嵌入網頁被對方禁止 | 卡片空白 | 偵測失敗時退回為連結卡片 |
